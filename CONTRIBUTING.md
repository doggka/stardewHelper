# Процесс

Локальный репозиторий без remote. Правила простые, но соблюдаются.

## Ветки

`main` всегда рабочий. Напрямую в него не коммитим.

Каждая задача — своя ветка:

```
feat/<что>     новая фича
fix/<что>      исправление бага
data/<что>     обновление данных с вики
chore/<что>    инфраструктура, документация
```

## Коммиты

Мелкие и по одной теме. Не «фильтры + база + поиск» одним куском — отдельно данные,
отдельно логика, отдельно вёрстка. Тогда `git bisect` находит виноватый коммит,
а откатить можно одну часть, а не всё сразу.

Сообщение: первая строка — что сделано, дальше по пунктам зачем и что изменилось.
Соавтор в конце:

```
Co-Authored-By: Craft Agent <agents-noreply@craft.do>
```

Для многострочных сообщений на Windows: `git commit -F <файл>`, а не `-m` с кавычками —
PowerShell ломает кириллицу и кавычки внутри.

## Слияние

```
git switch main
git merge --no-ff feat/моя-ветка
git tag v5
git branch -d feat/моя-ветка
```

`--no-ff` оставляет явный «пузырь» фичи. Откатить фичу целиком — один
`git revert -m 1 <хеш мерджа>`.

## Теги

После каждого слияния — `v5`, `v6`… Это точки «тут точно работало».

```
git switch --detach v4                      посмотреть старую версию
git restore --source=v4 stardew-helper/     вернуть файлы из неё
git log --oneline --graph --decorate        вся картина
```

## Проверка перед слиянием

Приложение запускается, экраны переключаются, консоль без ошибок, импорт сейва
даёт ожидаемые цифры. В `main` ничего не вливается, пока это не проверено.

## Чего не делаем

- Не коммитим `node_modules`, `.toolchain`, `dist` — они в `.gitignore`.
- Не трогаем папку игры и сейвы из кода репозитория без явной просьбы.
