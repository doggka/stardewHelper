# Stardew Helper

Десктопное приложение-помощник по узелкам Общественного центра Stardew Valley.
Windows, Electron + Vite + TypeScript.

## Запуск

Сборка даёт два варианта одной программы:

| | Что это |
|---|---|
| `release\Stardew Helper.exe` | портативный, один файл на 71 МБ. При запуске распаковывает себя во временную папку. Удобно утащить куда угодно |
| `release\win-unpacked\` | та же программа, уже распакованная (269 МБ). Стартует быстрее, но переносить надо папку целиком |

Оба без установки и без прав администратора. `win-unpacked` — промежуточный результат,
из которого собирается портативный файл, поэтому он никуда не денется.

**Важно:** `release` стирается при каждой пересборке. Ничего своего туда не клади —
папка `drop` для скачанных модов живёт отдельно, в данных приложения
(`%AppData%\Stardew Helper\drop`), и путь к ней показан на экране модов
с кнопкой «Открыть папку».

Разработка:

```
npm run dev        # Vite + окно Electron
npm run build      # сборка dist/ и dist-electron/
npm run dist       # портативный exe в release/
npm run typecheck  # tsc --noEmit
node scripts/check-saves.mjs   # что парсер видит в реальных сейвах
```

Node не ставится в систему — он лежит портативно в `../.toolchain/node`.
Перед npm добавь его в PATH:

```powershell
$env:Path = "C:\Users\doggm\projects\home-tools\.toolchain\node;" + $env:Path
```

## Как устроено

```
electron/        процесс Node: окно, IPC, чтение сейвов, поиск игры и модов
  main.ts        окно без системной рамки, IPC-хендлеры, список папок с сейвами
  preload.ts     мост contextBridge; nodeIntegration выключен
  saves.ts       разбор сохранений
  game.ts        поиск игры через libraryfolders.vdf, список установленных модов
src/             окно
  data/          узелки, локации, цены торговки, план по сезонам, база названий
  logic/         статусы, фильтры, поиск с опечатками
  screens/       онбординг и трекер
  ui/            разметка, модалка локации, тема
  bridge.ts      доступ к процессу Electron (+ дев-заглушка по ?mock)
```

Новая фича = новый файл в `data` и новый экран в `screens`, без правок в существующих.

`src/main.ts` в дев-режиме кладёт в `window.__dbg` состояние и функции статусов —
удобно прогонять сезоны и фильтры из консоли, не кликая по интерфейсу.
Экраны онбординга можно посмотреть в обычном браузере: `npm run dev`, затем
открыть адрес Vite с `?mock` — подставится заглушка моста с тестовыми сейвами.

## Экраны

1. **Приветствие** — список найденных сохранений с фермой, игроком и датой.
   Можно добавить ещё одну папку или работать вручную.
2. **Моды** — что делает каждый мод и зачем, со статусом «стоит / нет» из папки `Mods`.
   Ссылки открываются в системном браузере. Кнопка запускает `install-mods.ps1`.
3. **Трекер** — то, ради чего всё затевалось.

## Импорт сохранений

**Только чтение.** В файлы игры приложение не пишет ничего.

Прогресс берётся из `CommunityCenter → bundles`: ключ — индекс узелка, значение —
массив булей длиной 3 × (число предметов). Индекс `i` соответствует предмету №`i`;
когда узелок закрыт целиком, игра красит весь массив.

Состав узелков в сейве сверяется с нашим по длине массива. Если узелок не совпал,
он **пропускается**, а остальные импортируются: в версии 1.5 Животноводческий узелок
имел 11 предметов вместо 6, и из-за одного узелка терять остальные 29 глупо.
Если не совпало 4 и больше — это уже смешанные узелки, и импорт отключается целиком.

Прогресс хранится **отдельно по каждому сейву** (ключ `uniqueIDForThisGame`),
ручной режим — отдельным ключом. Прогресс старой браузерной версии при первом
запуске переезжает в ручной режим.

## Моды

`install-mods.ps1` ставит SMAPI и UI Info Suite 2 с GitHub, остальные открывает
на Nexus: оттуда скриптом без логина и премиума не скачать. Скачанные zip кладутся
в папку `drop`, повторный запуск раскладывает их по `Mods` (ищет `manifest.json`,
чтобы не получилось `Mods\Мод\Мод`). Путь к `drop` приложение передаёт параметром
`-DropDir` — сам скрипт его не угадывает.

На экране модов две кнопки:

- **Проверить** — `-DryRun`, ничего не качает и не меняет, лог виден в приложении;
- **Установить** — открывает окно PowerShell.

Окно, а не внутренний лог, потому что установщик SMAPI чистит экран через
`Console.Clear()` и без настоящей консоли падает с «Неверный дескриптор».
По той же причине его нельзя запускать через конвейер: любое перенаправление
вывода отбирает у него буфер консоли.

Режим передаётся строкой `mode: 'dry' | 'install'`, и моды ставятся только при
явном `'install'`. Раньше это был булев флаг, и его потеря при передаче молча
оборачивалась реальной установкой.

Файл должен быть сохранён в **UTF-8 с BOM** — иначе PowerShell 5.1 читает его
как ANSI и кириллица рассыпается.

## Известное ограничение

Иконка стоит на окне и в панели задач, но **не на самом `.exe`**: чтобы вшить её
в исполняемый файл, electron-builder распаковывает winCodeSign, а тот содержит
симлинки и без прав администратора или режима разработчика Windows не ставится.
Если включить режим разработчика, достаточно вернуть в `package.json`
`"win": { "icon": "build/icon.ico" }` вместо `signAndEditExecutable: false`.
